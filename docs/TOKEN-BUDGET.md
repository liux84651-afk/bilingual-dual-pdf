# Token 预算：为什么这么做便宜

一次 15 页双栏论文双语化的实测归因（同一任务，两种做法）。

| 环节 | 手工做法（边做边写引擎） | 本技能 | 差异来源 |
|---|---|---|---|
| 排版 | ~35% | ~5% | 现场写 600 行 canvas 引擎、改 5 遍 → 固定模板 + 200 行生成器 |
| 抽取文本进对话 | ~25% | ~3% | 逐页 dump（每页 1.5–2.5k）→ 只打印 3 行统计，正文落盘 |
| 读渲染图 | ~20% | ~3% | 读 20 张整页（1.5–2k/张）→ 1–2 张 5×3 缩略图 |
| 环境排查 | ~12% | ~5% | 一次性写进 TROUBLESHOOTING，不再重踩 |
| 翻译 | ~8% | ~8% | 两边都交给 subagent 并行（这部分不该省） |
| **合计** | **~30k tokens** | **~8–12k tokens** | **↓ 60–70%** |

## 六条硬规则

1. **正文不进口语**：脚本只输出统计；要核对用 `--show 3` 看前 3 段。
2. **读图 ≤ 2 张**：`verify.py --sheet 2` 生成缩略图；只在定位到具体缺陷时才单独读 1 页。
3. **脚本不重写**：抽取/排版/校验全部随技能附带，调用即用。
4. **翻译并行**：3 个 subagent 各自持有独立上下文，主会话只收 JSON 与覆盖率报告。
5. **机器校验优先**：占位符、缺译、页数、文本层 CJK 数——能用脚本判的绝不肉眼。
6. **id 稳定**：结构改完就冻结 id，之后只改文字，避免译文错位导致返工（返工最贵）。

## 什么时候值得多花 token

- 图表密集且裁图框需要微调：值得多看 1–2 张图确认 bbox；
- 术语体系复杂（法律/医学）：值得给 subagent 更长的术语表；
- 需要出版级排版：值得上 LaTeX 后端的调试成本。

除此之外，默认走 Markdown 后端即可。
